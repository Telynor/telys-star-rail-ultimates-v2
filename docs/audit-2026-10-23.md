# Ultimates and Memosprites audit — 23 October 2026

The review concentrates on encounter lifecycle, boss phases, summon ownership,
resources and initiative, damage attribution, D&D5e compatibility, and unnecessary
repeated work in actor preparation and HUD hooks.

## Corrections

| Area | Observed problem | Correction |
| --- | --- | --- |
| Boss isolation | Phase changes could overwrite a linked world Actor; final defeat chose the world Actor even for unlinked tokens. | Give each boss token a synthetic Actor and apply transitions and final defeat to that Actor. |
| Boss identity | Different tokens sharing a base Actor ID could advance the wrong boss and share one control row. | Match synthetic Actor UUIDs and identify control rows by token UUID. |
| Phase concurrency | Manual changes did not acquire the automatic transition lock. | Serialize both paths with the same encounter/combatant lock; forward secondary GM requests to the elected authority. |
| Phase contents | Recreated Item IDs could break references; cleanup could remove freshly transferred Item effects. | Keep embedded IDs, remap phase effect origins, and remove old effects before creating new Items. |
| Phase artwork | Shared NPC initiative framing could retain the root phase's portrait. | Follow the active phase source, falling back to the synthetic Actor for compendium phases. |
| Phase state | Final defeat did not restore dimensions, and failed writes could leave a partly replaced phase. | Restore original art and dimensions, mark the combatant defeated, clear defeat statuses on an active replacement, and roll back failed writes. |
| Transition damage text | A phase transition suppressed scrolling text for every creature. | Suppress only the transitioning token's area. |
| Deleted encounters | Light Cone cleanup attempted to update children and flags of a deleted Combat. | Skip deleted-parent writes, deduplicate cleanup, bind queued events to their original encounter, and preserve a newer encounter's runtime. |
| D&D5e 6 movement | Legacy movement setters produced compatibility warnings. | Read and modify `movement.speeds.walk` on version 6 and the legacy field on version 5. |
| Prepared bonuses | Cached prepared Light Cone stats survived combat end. | Clear prepared stats before preparation and rebuild from source. |
| Preparation cost | One stat evaluation repeatedly rebuilt the same combatant configs, equipment eligibility and team lists. | Cache only within that synchronous evaluation, so subsequent changes are immediately visible. |
| Boss HUD cost | Every render deep-cloned the full saved Actor inventory. | Read encounter state for rendering and clone only for a mutable transition. |
| Memosprite HUD cost | Unrelated actor updates, token movement, all body mutations and a one-second poll refreshed overlays. | Reconcile relevant owners, filter mutations, coalesce refreshes and restore overlays when the parent HUD redraws. Resolve synthetic damage sources directly through their token. |
| Memosprite damage | Formula-based identities ignored later identical rolls; Midi notifications could repeat damage or include missed targets. | Use captured damage IDs or per-Roll identities, defer Midi-managed rolls to completion, and honor hit targets. |
| Summon initiative | A completed cached setup job could prevent recreating a removed entry; a queued job could outlive its Combat. | Validate cached entries and recheck the live encounter around asynchronous setup. |

## Validation

Regression coverage exercises complete phase progression and final defeat, linked
and unlinked tokens, independent bosses sharing a source, manual/automatic races,
missing phase Actors, failed writes and retries, delayed resolution after Combat
deletion, transferred effects, preserved IDs and initiative, and secondary GM
forwarding. Existing suites cover skills, Ultimates, resources, spells, placement,
Light Cones, Multitype, NPC controls and settings.

Native summon integration uses D&D5e release 5.3.3 and 6.0.6 source. DOM checks use
the actual settings template and live summon markup; Chromium suites check the
rendered settings, help, NPC controls and summon HUD. Audit-branch CI is gated
against publishing releases.

These checks use a Foundry API shell, not the user's running world. Full-world
verification with Foundry v14, D&D5e 6.0.6, Midi-QOL, DAE and the user's other
modules remains a necessary smoke test before treating the changes as proven in
that environment. No audit can establish that every code path is bug-free or that
no further optimization is possible.
